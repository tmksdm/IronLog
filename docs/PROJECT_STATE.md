# Состояние проекта

## Текущий результат

Версия 0.24.1 устраняет пустой экран после завершения тренировки, защищает локальные данные при облачной синхронизации, проходит все проверки и готова к публикации в GitHub Pages и сборке Android.

## Подтверждённое состояние

- Локальные силовые и standalone-активности блокируют destructive cloud pull.
- Удаления переживают отсутствие сети в `cloud_delete_queue` и повторяются перед следующей синхронизацией.
- Дата standalone-турника передаётся в Supabase и восстанавливается в историю.
- «Удалить все силовые» не удаляет standalone-бег, турник и скакалку.
- Маршруты загружаются лениво; основной JS-чанк уменьшен примерно с 1,09 МБ до 275 КБ.
- Android-платформа создаётся локально командой `npm run build:android`; CI использует ту же команду.
- Финальное сохранение тренировки не конкурирует с автоматическим переходом на главную и показывает состояние загрузки.
- Непредвиденная ошибка рендера показывает экран безопасного перезапуска вместо чёрного экрана.

## Проверки

- `npm run lint` — пройдено без ошибок.
- `npm test` — 8 тестов пройдено.
- `npm run build` — production web-сборка пройдена.
- `npm run build:ghpages` — сборка GitHub Pages пройдена.
- `npm run build:android` — web build и Capacitor Android sync пройдены.
- `npm audit --audit-level=high` — 0 уязвимостей.

## Ограничения и блокеры

- APK не собирался локально: Java/Android SDK отсутствуют; сборка APK выполняется GitHub Actions или на машине с Android toolchain.
- Supabase из России может требовать VPN; реальная облачная синхронизация в этом этапе не проверялась с учётной записью.
- Настройки стоимости абонемента хранятся только в `localStorage` под ключом `ironlog_gym_cost` и не входят в JSON-бэкап. Старое значение из Git восстановить нельзя. Для текущего абонемента: начало 18.03.2026, окончание 18.09.2026.
- Откат программ при удалении всей силовой истории исторически сбрасывает программы целиком; перед его изменением нужно определить правило для оставшихся standalone-записей.
