# Состояние проекта

## Текущий результат

Версия 0.27.0 — полностью локальное приложение. Аккаунт, вход и облачная
синхронизация удалены: данные живут только на устройстве в SQLite, приложение
работает без сети, а резервная копия делается экспортом и импортом JSON. В этом же
выпуске: расширенный формат бэкапа с восстановлением одной транзакцией,
исправленная прогрессия упражнений без дополнительного веса, исправленная
прогрессия бега (повышение с конца дистанции, снижение с начала), откат программы
бега при удалении последней записи, номер сборки для доставки обновлений и
исправленный офлайн-запуск оболочки. Подробности — `docs/DECISIONS.md` и записи
`CHANGELOG`.

## Подтверждённое состояние

- Локальная база SQLite — единственный источник данных; сеть для работы приложения
  не нужна вовсе.
- ~~Локальные силовые и standalone-активности блокируют destructive cloud pull.~~
  ~~Удаления переживают отсутствие сети в `cloud_delete_queue`…~~ ~~Дата
  standalone-турника передаётся в Supabase…~~ Эти утверждения относились к
  облачной модели и **утратили силу** вместе с удалением облака: очереди удалений и
  синхронизации больше не существует, удаления выполняются локально.
- «Удалить все силовые» не удаляет standalone-бег, турник и скакалку.
- Маршруты загружаются лениво; основной JS-чанк уменьшен примерно с 1,09 МБ до 275 КБ.
- Android-платформа создаётся локально командой `npm run build:android`; CI использует ту же команду.
- Финальное сохранение тренировки не конкурирует с автоматическим переходом на главную и показывает состояние загрузки.
- Непредвиденная ошибка рендера показывает экран безопасного перезапуска вместо чёрного экрана.
- Новая версия PWA полностью кэшируется, автоматически активируется и сама перезагружает все управляемые окна, не полагаясь на JavaScript старой страницы.
- `version.json` получает краткие изменения автоматически из текущей записи `CHANGELOG`.
- Вес «до» редактируется из шапки активной и ещё не сохранённой тренировки.
- Карточка веса на итоговом экране и в деталях истории редактирует оба измерения и сразу пересчитывает среднее.
- Изменение завершённой тренировки сначала сохраняется в SQLite, затем запускает неблокирующую фоновую синхронизацию.
- Некорректные значения и вес вне диапазона 30–250 кг не сохраняются; пустое поле означает отсутствие измерения.
- Сборка создаёт версионированный `sw.js`; после перехода окон сохраняются текущий и один предыдущий кэш.
- `version.json` исключён из кэша оболочки, поэтому проверка новой версии продолжает работать.
- Смена управляющего worker вызывает автоматическую перезагрузку и не зависит от кнопок текущего интерфейса.
- Отмена и завершение силовой тренировки дожидаются незавершённого автосохранения перед очисткой снимка.
- Параллельные эффекты запуска не открывают SQLite повторно; ошибка инициализации показывает кнопку повторной попытки.
- Подсказка прошлого результата берёт все непропущенные рабочие подходы из одной последней завершённой тренировки упражнения; разминка не учитывается.
- Для упражнений с дополнительным весом подсказка прошлого результата показывает сохранённый рабочий вес перед повторами; для упражнений с собственным весом числовой вес не выводится.
- При отсутствии истории подсказка скрыта, а её данные сохраняются вместе со снимком активной тренировки для восстановления после перезапуска.
- Вес до тренировки отображается компактной кнопкой между таймером и закрытием; отдельная строка веса удалена.
- Скакалка отображается отдельной вкладкой статистики со средним количеством прыжков и числом тренировок за месяц и год; среднее округляется вниз до целого.
- Подтягивания сначала суммируются внутри каждой тренировки, затем усредняются по всем тренировкам месяца или года и округляются вниз до целого; число тренировок остаётся в таблице.
- Название упражнения в активной тренировке открывает компактную форму редактирования и сразу обновляется после успешной локальной записи.
- Переименование сначала сохраняется в SQLite, затем попадает в снимок активной тренировки и существующую фоновую синхронизацию Supabase.
- Пустое название отклоняется; при ошибке SQLite текущее название не меняется.
- Длинные названия в карточке активной тренировки переносятся на новые строки без обрезания многоточием.
- Таймер отдыха больше не считает количество вызовов `setInterval`: остаток выводится по сохранённому времени окончания и сразу корректируется после возврата из фона.
- Время окончания отдыха сохраняется в локальных снимках силовой тренировки и турника; старые снимки без нового поля остаются совместимыми.
- Завершение отдыха показывает плашку «Время отдыха закончилось» на 2,5 секунды только внутри IronLog; системные уведомления не используются.

## Ограничения и блокеры

- APK не собирался локально: Java/Android SDK отсутствуют; сборка APK выполняется GitHub Actions или на машине с Android toolchain.
- Настройки стоимости абонемента хранятся только в `localStorage` под ключом `ironlog_gym_cost` и не входят в JSON-бэкап. Старое значение из Git восстановить нельзя. Для текущего абонемента: начало 18.03.2026, окончание 18.09.2026.
- Откат программ при удалении всей силовой истории исторически сбрасывает программы целиком; перед его изменением нужно определить правило для оставшихся standalone-записей.
- Восстановление снимка активной тренировки проверено автотестами и живым прогоном, но не на живом телефоне после выключения экрана.
- Поведение страницы после автоматического обновления service worker в автоматическом браузере не наблюдаемо (раздел 7 `docs/HANDOFF.md`); на живом телефоне обновление проверено владельцем.

## Точка входа

- Релизная версия: `src/version.ts` (`APP_VERSION`, `CHANGELOG`), `package.json`.
- Прогрессия бега: `src/utils/runningProgram.ts` и `src/utils/runningProgram.test.ts`
  (правила — `docs/DECISIONS.md`, «Прогрессия беговой программы»).
- Прогрессия упражнений без веса: `src/utils/reps.ts`.
- Резервная копия: `src/utils/exportData.ts`, `src/utils/importData.ts`.
- Публикация: `.github/workflows/deploy.yml` (production, вручную);
  проверки — `.github/workflows/ci.yml`.
